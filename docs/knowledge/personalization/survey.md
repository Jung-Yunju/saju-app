# 개인화 설문 설계 (P4-01)

작성: 개인화 분석 연구원. 코드 원본: `src/engine/personalize/survey.ts` (이 문서와 다르면 코드가 기준 — 바꿀 때 둘 다 갱신).
출생 정보(생년월일시·성별)는 설문이 아니라 기본 입력이다. 이 설문은 그 위에 얹는 **선택 문항**이다.

## 0. 원칙
1. 모든 문항은 **선택형**이고 **건너뛸 수 있다**. 자유 서술 문항은 없다(이름·사연이 외부 AI로 흘러가는 길을 줄이기 위해).
2. 풀이의 어느 장에서 어떻게 쓰는지 적을 수 없는 문항은 두지 않는다. 12개 문항(상한 15개).
3. 답은 `source:"user"` 사실로만 저장·전달된다. 사주 경향(`source:"chart"`)과 한 배열에 섞지 않는다.
4. 사용자 답은 풀이에서 **맞히는 증거로 쓰지 않는다**(`useAs:"background-only"`). 연도가 걸린 답은 그 해를 맞히기 서술에서 뺀다.
5. MBTI는 자기보고 정보다. 원국·운 계산 근거로 쓰지 않고 사주와 맞다/틀리다를 판정하지 않는다. 발현 비교(expression 엔진, D-035 — [expression-engine.md](expression-engine.md))에서 '스스로 느끼는 모습' 신호로만 쓰고 결과는 항상 추론으로 표시한다.

## 1. 문항 (12개)

| # | id | 질문 | 유형 | 선택지 |
|---|---|---|---|---|
| 1 | concernTopic | 요즘 가장 마음이 가는 주제 | 복수(최대 2) | 연애·결혼 / 돈·재물 / 일·진로 / 가족 / 사람 관계 / 나 자신 알기 / 앞으로의 방향 |
| 2 | horizon | 어느 때가 궁금한지 | 단일 | 올해 / 앞으로 3년쯤 / 큰 흐름 전체 |
| 3 | relationshipStatus | 지금 연애·혼인 상태 | 단일 | 혼자 / 만나는 사람 있음 / 결혼 / 그 밖이거나 말하고 싶지 않음 |
| 4 | hasChildren | 자녀 유무 | 단일 | 없음 / 있음 |
| 5 | occupationStatus | 지금 하는 일 | 단일 | 학생 / 구직 중 / 직장 / 사업·장사 / 프리랜서 / 집안일·돌봄 / 은퇴 / 그 밖 |
| 6 | careerFeeling | 지금 일에 대한 마음 | 단일 | 만족 / 그저 그래요 / 바꿀까 고민 / 새로운 걸 준비 |
| 7 | loveFocus | 연애에서 가장 궁금한 것 | 단일 | 새 인연 / 지금 관계 이어 가기 / 결혼 흐름 / 지난 인연 돌아보기 |
| 8 | moneyFocus | 돈 이야기에서 가장 궁금한 것 | 단일 | 꾸준한 수입 / 수입 늘리기 / 내 일·사업 시작 / 모으고 지키는 습관 / 특별히 없음 |
| 9 | birthOrder | 형제자매 중 순서 | 단일 | 외동 / 첫째 / 중간 / 막내 |
| 10 | lifeEvents | 이미 지나온 큰 일(+해) | 복수+연도 | 결혼 / 출산·입양 / 취업·이직·전직 / 입학·졸업·진학 / 이사·이민 / 사업 시작 |
| 11 | mbti | MBTI(알면) | 단일 | 16유형 |
| 12 | toneStrength | 말씀의 느낌 | 단일 | 부드럽게 돌려서 / 적당히 / 솔직하게 짚어서 |

혼인 상태에 이혼·사별 선택지는 두지 않는다(상처가 되는 질문을 피하고, 그 경우를 "그 밖이거나 말하고 싶지 않음"으로 받는다).

## 2. 문항별 쓰임 (장 이름은 제안 — 콘텐츠 작가가 확정)

| id | 쓰는 장 | 어떻게 쓰나 | 쓰지 않는 방식 |
|---|---|---|---|
| concernTopic | 총론·마무리 조언 | 길게 다룰 장의 순서·분량을 정한다 | 사주 판단 자체를 바꾸지 않는다 |
| horizon | 올해·세운 / 대운 흐름 | 세운과 대운 중 분량 비중 | - |
| relationshipStatus | 연애·결혼 / 인간관계·가족 | 배우자 관련 글자를 "지금 상황에 맞는 장면"으로 옮긴다 | "결혼하셨군요"처럼 맞히기 금지 |
| hasChildren | 인간관계·가족 / 재물 | 식상·관성 해석에서 자녀 이야기를 꺼낼지 결정 | 없다고 했을 때 자녀 암시 금지 |
| occupationStatus | 직업·진로 / 재물 / 대운 | 같은 십성을 학생·직장인·사업가 장면으로 다르게 옮긴다([life-stages.md](life-stages.md)) | 직업을 사주로 단정 금지 |
| careerFeeling | 직업·진로 | 이직·전환 운을 "지키는 쪽/움직이는 쪽" 중 어디에 무게 둘지 | 퇴사·이직 결정을 대신하지 않음 |
| loveFocus | 연애·결혼 | 세부 소제목·분량 | - |
| moneyFocus | 재물 | 재성을 월급형/사업형/저축형 장면으로 | 종목·투자 조언 금지 |
| birthOrder | 성격·기질 / 인간관계·가족 | 비견·겁재·인성을 집안 안의 위치로 옮길 때 참고 | 부모·가정사 단정 금지 |
| lifeEvents | 대운 흐름 / 올해·세운 | **그 해를 맞히기 문장에서 뺀다**(`noGuessYears`) | 사주로 "설명"하거나 "맞혔다"고 쓰지 않음 |
| mbti | 성격·기질 / 발현 비교 | 비유·말씨 참고 + 발현 비교(D-035)의 '스스로 느끼는 모습' 신호(결과는 항상 추론) | 원국·운 계산 근거로 사용 금지, 사주와 맞다/틀리다 판정 금지, MBTI만으로 경험 단정 금지 |
| toneStrength | 전 장 말투 | 표현 세기(여지를 두는 정도)만 조절 | 금지 주제·원칙은 그대로 |

## 3. 상품별 문항표 (R = 필수: 먼저·눈에 띄게 묻는다 / O = 선택 / - = 묻지 않음)
"필수"도 건너뛸 수 있다. 건너뛰면 해당 정보 없이 사주만으로 풀이한다.

| 문항 | 무료 | 기본 | 연애 | 재물 | 직업 | 궁합 | 고민 |
|---|---|---|---|---|---|---|---|
| concernTopic | O | O | O | O | O | O | **R** |
| horizon | O | O | O | O | O | - | O |
| relationshipStatus | - | O | **R** | - | - | **R** | O |
| hasChildren | - | O | O | O | - | - | - |
| occupationStatus | - | O | O | **R** | **R** | - | O |
| careerFeeling | - | - | - | - | **R** | - | - |
| loveFocus | - | - | **R** | - | - | O | - |
| moneyFocus | - | - | - | **R** | - | - | - |
| birthOrder | - | O | O | - | - | O | - |
| lifeEvents | - | O | O | O | O | - | O |
| mbti | O | O | O | - | - | O | - |
| toneStrength | O | O | O | O | O | O | O |

- 무료는 4문항 이하(concernTopic·horizon·mbti·toneStrength)로 짧게 — 입력 부담이 이탈로 이어지지 않게.
- 필수는 연애 2개, 재물 2개, 직업 3개, 궁합 2개, 고민 1개. 어느 상품이든 한 화면에서 6문항을 넘기지 않는다.
- 궁합: 상대 생년월일은 설문이 아니라 별도 입력이다. 설문은 본인 쪽 상황만 묻는다.
- 고민 상품의 구체적인 사연은 자유 서술이 필요할 수 있다. 이 설문 구조에는 넣지 않았다 — 도입 여부는 **대표 결정 사항**(§6).

## 4. 묻지 않는 것과 이유
| 항목 | 이유 |
|---|---|
| 건강 상태·병력·장애 | 민감정보. 풀이 품질에 꼭 필요하지 않고, 사주로 건강을 단정하는 것은 금지 주제(CLAUDE.md 3절·콘텐츠 규칙) |
| 종교·정치 성향·성적 지향·성생활 | 민감정보이고 풀이에 쓸 일이 없다 |
| 이혼·사별·유산·사고·실직 같은 상처 경험 | 상처가 될 수 있고 "맞히기" 유혹을 키운다. 필요하면 사용자가 "그 밖" 선택 또는 비워 둔다 |
| 소득·자산·부채 금액 | 개인정보 부담이 크고 투자 조언으로 오용될 수 있다 |
| 이름·연락처·주소·직장명 | 풀이에 불필요. 이름은 호칭용으로 기본 입력에서 이미 받는 것만 쓴다 |
| 부모·양육 환경 | 사주로 "부모 덕" 같은 단정을 끌어낼 위험(SYSTEM_PROMPT 원칙 4). 출생 순서만 받는다 |
| 군필 여부 | 나이·성별로 단계 규칙만 적용(life-stages.md). 직접 묻지 않는다 |
| 자유 서술 | 외부 AI 서비스로 의도치 않은 개인정보가 새는 것을 막는다 |

## 5. 개인정보 처리 메모 (제안 — 법무 검토 필요)
- 설문 답은 건강·종교 등 **민감정보에 해당하지 않도록** 설계했다. 그래도 혼인·자녀·직업 상태는 사생활이므로 수집 목적(풀이 맞춤)과 선택 사항임을 화면에 밝힌다.
- **만 14세 미만**: 설문을 보여 주지 않고 답이 와도 풀이에 쓰지 않는다(코드: `MIN_SURVEY_AGE=14`). 개인정보 보호법상 만 14세 미만은 법정대리인 동의가 필요하다.
- **외부 AI 전송 최소화**: 콘텐츠 엔진에는 `PersonalContext`만 보낸다. 이름·이메일·생월일·출생지는 담기지 않고, 출생 연도·만 나이·코드값 답만 간다.
- **보관 기간 제안**
  - 설문 원답: 풀이 결과(리포트)와 같은 수명. 회원은 **결제일로부터 1년** 뒤 삭제하거나 사용자가 요청하면 즉시 삭제, 탈퇴 시 즉시 삭제.
  - 비회원·미결제(무료 체험): **생성 후 7일** 뒤 삭제(재열람 용도).
  - 로그·분석 데이터에는 원답을 남기지 않는다(검증 오류에도 원문 값을 담지 않도록 구현했다).
  - 위 기간은 제안이며 **대표 결정 + 법무 검토** 사항이다.
- 사용자는 언제든 개별 답을 수정·삭제할 수 있어야 한다(백엔드·프론트 요구사항).

## 6. 대표 결정 필요
1. 설문 길이: 12문항(상품별로는 3~8문항 노출). 줄이려면 우선순위 낮은 순: birthOrder → hasChildren → loveFocus.
2. 보관 기간(위 §5 제안) 승인.
3. 고민 상품에 자유 서술 칸을 둘지(두면 외부 AI로 가는 개인정보 위험이 커져 별도 마스킹 설계 필요).
4. 연도 입력(lifeEvents)을 "맞히기 방지" 용도로 유지할지. 사용자에게는 "비켜 가기 위한 정보"라고 설명해야 한다.
