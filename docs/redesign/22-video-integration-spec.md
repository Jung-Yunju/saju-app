# 운명비서 영상 연동·UI 명세 (대표 2026-11-28) + 개발 계약

> 대표 명세서 원문 요지 + 개발팀이 맞춰 만들 수치 계약. 실제 영상·이미지·효과음은 그래픽 담당 납품 전 — 지금은 **같은 이름·같은 규격의 임시 자산**(ffmpeg로 만든 시험 영상 포함)으로 개발·시험한다.

## 1. 흐름
1. 뷰포트 비율로 PC(16:9)·모바일(9:16) 자산 분기(가로 ≥ 세로 → PC).
2. **인트로 영상(장면 01~07, 실제 55~65초)**: 우측 상단 절제된 '건너뛰기'. 자동 재생 차단(저전력 등)·로딩 실패·움직임 줄이기 → 즉시 **장면 07 마지막 정지 이미지(펼친 고서 탑뷰)**.
3. **장면 07 끝 → 입력**: 영상 마지막 프레임과 같은 구도의 고해상도 정지 이미지로 이음새 없이 전환. 영상 속 글자를 입력란으로 쓰지 않고, **빈 종이 영역**의 위치·비율·조명(좌측 따뜻한 등불, 우측 서늘한 그림자)에 맞춰 **실제 HTML 입력 UI를 오버레이**. 항목: 이름·성별·양력/음력·윤달·생년월일·태어난 시각(+모름)·출생지역. 버튼 「나의 운명비서 열기」.
4. **장면 08 이름 각인(웹 직접 구현, 약 3초)**: 클릭과 동시에 분석 API를 백그라운드 호출. 0.0~0.6초 폼 테두리·라벨·버튼 페이드아웃 → 0.6~2.2초 **이름만 고서 중앙에 남아** 먹이 스며들듯 번짐(blur→0, multiply, 먹색 #141310 또는 인장색 #702F2B), 마른 붓 효과음 → 2.2~3.0초 가장자리 비네팅 + 0.3초 크로스페이드로 결과 진입 영상.
5. **장면 09~10 결과 진입 영상(약 12~15초)**: 책이 떠올라 할머니 옆으로(09) → 책장이 스스로 넘어감 → 할머니가 손으로 눌러 멈춤(10). **API가 늦으면 '책장이 넘어가는 구간'을 짧게 루프**, 응답이 오면 '손을 얹어 멈추는 컷'으로 이어 재생.
6. 장면 10 마지막 멈춘 고서 페이지 → 결과 화면 **디졸브**. 무료·유료 모두 같은 서재 색·고서 디자인.

## 2. 자산 이름(납품 규격)
`intro_pc_16x9.mp4` / `intro_mobile_9x16.mp4` (+ 같은 이름 .webm 선택) · `result_entry_pc_16x9.mp4` / `result_entry_mobile_9x16.mp4` · `book_topview_pc_16x9.png` / `book_topview_mobile_9x16.png` · `sfx_brush_close.mp3`. 위치 `public/unmyeong/final/`(납품) / `public/unmyeong/placeholder/`(임시).

## 3. 수치 계약 (자산 목록 `src/lib/unmyeong/assets.ts`의 `media` 항목 — 납품 시 숫자만 교체)
- **종이 영역(오버레이 위치, 이미지 대비 %)**: PC 16:9 → x 30~70%, y 12~88% / 모바일 9:16 → x 8~92%, y 18~86%. 이름 각인 중심 = 종이 영역 가운데, 위에서 32% 지점.
- **조명**: 좌측 따뜻한 등불(#E2D8C5 쪽 밝음), 우측 서늘한 그림자 — 오버레이 글자에도 미세한 좌→우 명암.
- **결과 진입 영상 구간(초)**: 임시 영상 기준 전체 12.0 / 루프 구간 6.0~9.0(책장 넘김) / 멈춤 컷 9.0~12.0. 실제 영상 납품 시 그래픽 담당이 이 세 값을 알려 줌.
- **이미지 맞춤**: 영상·정지 이미지 모두 `object-fit: cover` 기준, 오버레이는 같은 cover 변환을 따라 계산(화면 비율이 달라도 종이 위에 정확히).
- 효과음: 사용자의 클릭 직후에만 재생(자동 재생 규칙), 실패해도 진행.
