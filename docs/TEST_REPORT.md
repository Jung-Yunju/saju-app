**새로 발견한 문제 (일반 설명, 심각도)**
1. 높음(사용성·매출): 운영 기본값에서 무료 경로가 닫히는데, 화면에는 결제로 이어지는 신청 경로가 없다.
2. 중간: 생성 실패 뒤 다시 시도 횟수에 상한이 없어 풀이 1건당 AI 비용 상한이 없다. 운영 설정의 응답 길이 제한이 작아 실패가 잦을 가능성이 있음(실호출 미검증).
3. 중간: 결제는 승인됐는데 사용자가 화면을 떠나면 풀이가 없는 주문이 남을 수 있고, 자동 대사(토스 웹훅 등)가 없다.
4. 낮음: 생성 경로가 연결 주문의 결제 상태를 다시 확인하지 않는다(심층 방어 부족, 현재 생성 경로로는 미결제 풀이가 만들어지지 않음).
5. 낮음: 시간 초과 뒤에도 AI 요청 자체는 취소되지 않는다.
6. 낮음: 대기 화면이 첫 요청 유실 시 안내 없이 계속 기다리는 경우, 결제 완료 화면의 예외 처리·문구, 결제 완료 주소에 생년월일이 실림(개인정보 최소화), `VERIFYING` 상태 화면 미처리, 무료 허용 판단이 `NODE_ENV` 미설정 시 열림, 주문 준비 경로 호출 빈도 제한 없음, 서버 오류 로그에 입력값이 섞일 수 있음.

보안 점검(코드 읽기 + 실행):
- 스크립트는 페이지 안 인라인 2개뿐, 외부 스크립트 0. 인라인 이벤트는 `<link onload="this.media='all'">`(고정 문자열) 하나뿐 — 사용자 입력 없음. `innerHTML`·`eval`·`document.write` 없음. 주소 매개변수는 정규식 검사와 숫자 변환에만 쓰인다. — 통과
- 저장소 차단 흉내(`localStorage` 접근 시 SecurityError) / 용량 초과 흉내(`setItem` 예외): 두 경우 모두 페이지 오류 0, 재생·종료·다시 보기 정상, 매번 인트로가 다시 재생(생략 기억 못 함 — 의도대로). — 통과

결함·권고(담당: 디자인 실장, 실서비스 이식 시 프론트엔드):
- **I-1 (중간) ① lamp 헤더 대비 미달.** 끝 장면에서 헤더 배경이 밝은 방 벽이 되는데 글자색은 밝은 `#f3eadb`, 건너뛰기 버튼은 `#b8ad9e` 글자 + 반투명 어두운 바탕. 14~15px 굵은 글씨라 4.5:1이 필요한데 2.5~3.6:1. 재생 첫 장면(?at=0)도 같다. REVIEW.md의 "버튼 10.5:1"은 실제 화면과 다름. ① 채택 시 수정 필요.
- I-2 (낮음) 김(steam) 애니메이션이 종료 타이머보다 늦게 끝난다: ③ 압축본 4.1초 > 3.05초, ② 전체판 6.5초 > 5.4초. 종료 시 김이 중간에서 끝 상태로 '툭' 바뀐다(끝 상태가 같아 눈에 띄는 정도는 작음).
- I-3 (낮음, 시안 전용) 검수용 `?at=` 에 숫자가 아닌 값이 오면 페이지 오류(currentTime non-finite). 시작 버튼은 그대로 보임. 실서비스 이식 시 `?at=`·`?fresh=`·`window.replay/finish`·`message` 수신(출처 확인 없음 — 재생만 다시 함)은 빼거나 개발 모드로 한정할 것.
- I-4 (권고·개인정보) Google Fonts를 브라우저가 직접 받으면 방문자 IP가 Google로 간다. 실서비스는 `next/font`(빌드 시 자체 호스팅)로 바꾸면 외부 요청이 0이 되고 글꼴 334~359KB도 줄일 수 있다.
- 장식 글자(① 잠든 고양이 'z', 장식 SVG 안·aria-hidden)는 대비 1.3~1.5:1이나 장식이라 기준 대상 아님. ③ 오행 글자는 떨어지는 도중(1.4초) 한때 3.4:1 — 등장 효과 중간값이라 결함으로 보지 않음.
