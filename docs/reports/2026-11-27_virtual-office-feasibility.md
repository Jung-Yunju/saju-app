# AI 직원 가상 사무실 — 수집 가능 정보 조사 및 구현 방안 보고

> 보고일 2026-11-27 · 보고자 총괄실장 · 상태: **대표 승인 대기 (개발 미착수)**

## 1. 결론 요약
- **실제 업무 연동은 가능하다.** 이 클라우드 환경에서 Claude Code Hooks를 시험해 보니, 어느 직원이 언제 어떤 도구로 어떤 파일을 다루는지가 실시간 이벤트로 기록됐다(아래 3절 실측).
- 남은 결정은 **화면을 어디에 띄우느냐**다.
  - 방안 A: claude.ai 비공개 페이지. 추가 비용 0원, 빠르게 구축할 수 있다. 다만 갱신은 수 분 간격이다.
  - 방안 B: 독립 관리 사이트. 몇 초 단위 실시간이지만 서버·DB가 필요하다.
- 권고: **A로 먼저 만들어 써 보고, 필요하면 B로 확장한다.** 두 방안 모두 수집부(Hooks)와 화면(픽셀아트 사무실)을 같은 코드로 쓰도록 설계하므로, B로 넘어갈 때 다시 만들지 않는다.

## 2. 조사 방법
1. Claude Code 공식 문서 확인: Hooks, 서브에이전트, 텔레메트리, 클라우드 환경 (code.claude.com/docs)
2. 이 클라우드 세션의 작업 기록 파일 구조 분석 (오늘 실제 직원 활동 기록 사용)
3. **실측 시험**: 기록 전용 Hook을 잠시 설치하고 가벼운 직원에게 파일 1개를 읽게 한 뒤 이벤트를 확인하고 원래대로 되돌렸다.

## 3. 실측 결과 — 이 환경에서 실제로 받은 이벤트
| 순서 | 이벤트 | 담긴 정보 |
|---|---|---|
| 1 | 총괄실장이 직원 호출 (PreToolUse: Agent) | 업무 설명, 직원 종류 |
| 2 | **SubagentStart** | `agent_type = business-strategist`, `agent_id` |
| 3 | **PreToolUse** (직원) | 직원 이름, 도구 `Read`, 파일 `docs/COST_REPORT.md` |
| 4 | PostToolUse (직원) | 도구 결과 |
| 5 | **SubagentStop** | 직원 이름, 마지막 보고문, 직원 작업기록 파일 경로 |

- 설정을 바꾸자 세션을 다시 시작하지 않아도 즉시 반영됐다.
- 총괄실장(메인 세션)의 이벤트에는 직원 이름이 비어 있다. 그래서 "직원 이름 없음 = 총괄실장"으로 구분할 수 있다.

## 5. 화면 위치 — 두 가지 방안

### 방안 A. claude.ai 비공개 페이지 (권고 1단계)
```
직원 활동 → Hooks(비동기, 업무 방해 없음) → 작업공간 이벤트 로그
          → 총괄실장이 직원 시작·종료 및 매 작업 단계마다 상태를 페이지 DB에 기록
          → 대표 화면(픽셀아트 사무실)이 DB 변경을 실시간 구독해 반영
```
- 접근 권한: 기본 비공개라 **대표님 claude.ai 계정만 열 수 있다.** 별도 로그인을 만들 필요가 없다.
- 이력 저장: 페이지 DB에 영구 저장된다(세션이 끝나도 남음).
- 비용: **추가 0원.** 서버·DB·도메인이 필요 없다.
- 한계:
  - 화면 갱신은 총괄실장이 기록하는 시점, 즉 직원 출근·퇴근과 작업 단계마다(대략 수 초~수 분 간격)다. 그 사이의 세부 활동은 로그로 모아서 보여 준다.
  - 세션이 꺼져 있으면 갱신되지 않고 "확인 불가"로 표시한다.
  - 기록할 때마다 총괄실장 토큰이 조금씩 든다(갱신 1회당 수백~수천 토큰).

### 방안 B. 독립 관리 사이트 (권고 2단계, 선택)
```
직원 활동 → Hooks(http, 비밀 토큰) → 관리 서버(Next.js, 고객 사이트와 별도 프로젝트)
          → DB(Neon 별도 데이터베이스) → SSE 실시간 전송 → 대표 화면
```
- 실시간성: 도구 사용 1회마다 **수 초 이내** 반영된다.
- 접근 권한: Google 로그인 + 대표 이메일만 허용.
- 필요한 조치(대표 승인 사항):
  - 클라우드 환경에 관리 서버 주소 접속 허용
  - 비밀 토큰 등록(환경 비밀값 기능 사용, 코드에 넣지 않음)
  - Vercel 프로젝트 1개 추가
- 장점: 나중에 대표님 PC에서 Claude Code를 직접 쓸 때의 활동도 같은 화면에 모을 수 있다.

### 비교
| 항목 | A. 비공개 페이지 | B. 독립 관리 사이트 |
|---|---|---|
| 실시간성 | 작업 단계마다 (수 초~수 분) | 도구 사용마다 (수 초) |
| 추가 월 비용 | 0원 | Vercel Pro $20/월(고객 사이트 상용화 때 어차피 필요, 같은 팀이면 추가 좌석 없음 — 가입 시 확인) + Neon 소량(무료 범위 또는 월 수천 원 수준, 추정) |
| 로그인 | claude.ai 계정(기본 비공개) | 직접 구현(Google + 이메일 허용 목록) |
| 개발 규모 | 작음 | 중간 |
| 개발 토큰(추정, API 환산) | 약 100~150만 토큰 ≈ $25~40 | A에 더해 약 200~300만 토큰 ≈ $50~80 |
| 대표 승인 필요 | 개발 착수만 | 개발 착수 + 네트워크 허용 + 비밀값 + Vercel 프로젝트 |

개발 토큰은 대표님 구독 범위 안에서 사용되며 별도 청구는 없다. 단, 구독의 사용량 한도는 소모된다.

## 6. 기술 구성 (두 방안 공통)
- 화면: React + **Phaser 3** (2D 게임 엔진, MIT 무료).
  - 타일맵·스프라이트 애니메이션·경로 이동이 내장돼 있어 사무실 구현에 유리하다.
  - PixiJS(렌더링 전용)보다 개발이 빠르다.
- 그래픽: 디자인 실장이 **직접 그린 독창적 픽셀아트**.
  - 직원 10명 캐릭터, 6개 공간(대표실·개발실·명리학 연구실·디자인실·회의실·휴게실), 턱시도 고양이 복자.
  - 기존 게임의 캐릭터나 화풍을 베끼지 않는다.
  - 외부 에셋을 사면 라이선스를 확인해야 하고 수만 원 수준(추정)이므로, 기본은 자체 제작.
- 수집: Hooks(비동기 command)가 이벤트를 JSON 한 줄로 기록한다.
  - 기록 항목: 도구 이름, 파일 경로, 시각, 직원.
  - **명령 내용·파일 내용·개인정보는 기록하지 않는다.** `.env` 경로는 가린다.
- 상태 규칙: 마지막 이벤트 후 10분이 지나면 "확인 불가"로 바꾼다. 세션 종료는 "퇴근".
- PC·모바일 대응: 화면 크기에 맞춰 사무실 전체 보기 또는 방 단위 보기로 전환하고, 직원 상세는 하단 시트로 띄운다.

## 7. 확인한 제약과 위험
- 작업기록 파일 형식은 공식 문서상 **내부 형식이라 버전마다 바뀔 수 있다.** 그래서 주 데이터는 공식 Hooks로 받고, 작업기록은 토큰 집계의 보조로만 쓴다.
- 클라우드에서 Hooks가 외부 주소로 보내는 요청에 네트워크 허용 목록이 적용되는지는 문서에 없다. 방안 B에서 시험이 필요하다.
- 텔레메트리(OpenTelemetry)로 직원별 비용을 받는 방법도 있다. 하지만 클라우드에서는 저장소가 아니라 환경 설정과 별도 수집 서버가 필요해 방안 B 이후로 미룬다.
- 고객 사주 사이트와는 코드·DB·주소를 **완전히 분리**한다.

## 8. 대표 결정 필요 사항
1. 방안 선택: **A부터(권고)** / 처음부터 B / 보류
2. 캐릭터 화풍: 2D 픽셀아트(탑다운) / 아이소메트릭. 권고: 탑다운 픽셀아트. 모바일에서 잘 보이고 제작이 빠르다.
3. 복자 캐릭터 확정(앞선 결정 대기 4번과 연결): 고양이 이름이 '복자'라면 사무실 마스코트로 쓴다.
