# 1단계 — 무료 운명비서 공개 절차 (대표 승인용)

> 총괄실장 작성, 2026-11-28. 아래 ①은 **대표 승인 전에는 실행하지 않는다**(공통 규칙 15).

## 현재 상태 (확인한 사실)
- 작업 브랜치는 main보다 커밋 124개 앞서 있고, main에만 있는 커밋은 0개다 → 그대로 앞으로 감기(fast-forward)로 합칠 수 있다(충돌 없음).
- CI(자동 검사)는 타입 검사·린트·테스트·**운영 빌드**까지 돌린다.
- DB 구조 변경(마이그레이션)은 준비만 되어 있다. 옛 DB 호환 장치(`src/lib/db-legacy.ts`) 덕분에 **`DB_SCHEMA_V3`를 켜지 않으면** 마이그레이션 없이 배포해도 기존 화면이 깨지지 않는다(실제 PostgreSQL 16으로 확인, `docs/DATABASE.md` 4.0절).
- 무료 운명비서(`/unmyeong`)는 DB·AI·로그인을 쓰지 않는다. 이름은 서버로 가지 않는다. 비용은 서버 사용량뿐(기존 Vercel 요금제 안).
- **확인 불가**: Vercel이 main에 합치는 즉시 자동 배포하도록 연결되어 있는지(Vercel 화면은 볼 수 없음). 보통은 자동 배포다.

## 대표 승인 후 실행 순서
1. 위 P1~P3 끝, 품질검증 통과 보고.
2. Vercel 환경변수 확인(대표 화면에서): `DB_SCHEMA_V3` **없음**, `READING_ENGINE` **없음**. 기존 값(`DATABASE_URL`, `AUTH_*`, `TOSS_*`, `NEXT_PUBLIC_SITE_URL`, `ALLOW_FREE_READING`)은 손대지 않는다.
3. main에 합침(앞으로 감기) → Vercel 자동 배포.
4. 배포 직후 확인: `/unmyeong` 입력→결과, 기존 `/`·`/free`·로그인·풀이 목록 열림, Vercel 로그에 "column does not exist" 없음.
5. 문제 시 되돌리기: Vercel에서 직전 배포로 "Promote/Rollback"(1분 안). DB는 바뀐 것이 없다.

## 대표 결정이 필요한 것
- **D1. 공개 방식** — ★ 추천: 먼저 `주소/unmyeong`으로만 열고(홈은 그대로), 대표님 실기기 확인·지인 반응 뒤 홈(`/`)을 운명비서로 바꾼다. / 또는 처음부터 홈 전환.
- **D2. main 합치기·배포 승인** — P1~P3 완료 보고 뒤.
