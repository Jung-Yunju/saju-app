# 견본 풀이 채점 기준표 (P4-05)

> 관리: 품질검증·보안 담당자 · 최초 작성 2026-11-27 · 카드 P4-05
> 목적: 대표의 질문 **"이 풀이에 돈을 받을 만한가?"** 에 같은 잣대로 답한다. 우리 견본 10편과 경쟁사 유료 풀이 1~2편을 **같은 표**로 채점한다.
> 이 표가 재는 것: 글이 사실표와 맞는지, 이 사람만의 글인지, 쓸모 있고 안전한지, 읽을 맛이 나는지.
> 이 표가 재지 **않는** 것: 명리 해석의 미래 예측이 맞는지. 그건 이 표로 잴 수 없고, 맞는다고 증명된 것도 아니다.

## 0. 한눈에

| # | 항목 | 한 줄 정의 | 누가 매기나 | 자동 상한 |
|---|---|---|---|---|
| 1 | 정확성 | 근거로 든 글자·십성·합충·연도가 사실표와 맞는가 | 품질검증 + 대표 | 있음(검증기) |
| 2 | 구체성 | "다른 사주에 줘도 통하는 문장"이 적은가 | 품질검증 + 대표(표본 검사) | 있음(근거 표지·교차 중복) |
| 3 | 깊이 | 현상 → 원인(글자) → 시기 → 쓰는 법까지 가는가 | 품질검증 | 없음(보조 지표만) |
| 4 | 할미 목소리 | 말투 가이드 준수, 따뜻함·재치·신랄함 균형, 말버릇 남용 없음 | 품질검증 + 대표 | 있음(반복 표현) |
| 5 | 유용성 | 오늘부터 할 일·갈림길 기준이 실제로 할 수 있는 일인가 | 대표 + 품질검증 | 없음(보조 지표만) |
| 6 | 안전 | 금지 주제·공포·성별 판정·과학 단정이 0인가 | 품질검증 | 있음(검증기) |
| 7 | 개인화 | 사용자가 말한 사실을 배경으로만 쓰고 맞히지 않는가 | 품질검증 | 있음(검증기) |
| 8 | 읽는 재미·재방문 | 끝까지 읽고 싶고 1년 뒤 다시 오고 싶은가 | **대표 판정** | 없음 |

**점수 규칙**
- 각 항목 1~5점, 정수. 반 점 없음(망설이면 낮은 쪽).
- **최종 점수 = min(사람 점수, 자동 상한)**. 자동 값은 천장이다 — 사람 점수를 깎을 수는 있어도 올려 주지 않는다.
- 자동 상한이 "미검증"(사실표가 없어 검증기를 못 돌림)이면 그 편은 합격 판정을 내릴 수 없다.
- 채점은 견본 한 편(한 사람의 풀이 전체) 단위다. 장마다 점수를 매기지 않고, 가장 약한 장이 그 편의 점수를 끌어내린다고 보고 매긴다.

## 1. 정확성

**정의**: 풀이가 근거로 든 글자(간지 한자), 그 글자의 십성, 합·충 같은 관계, 연도의 간지가 사실표(FactSheet)에 실제로 있고 맞는가. AI가 사실표에 없는 관계를 지어내지 않았는가.

| 점수 | 기준 |
|---|---|
| 5 | 검증기 정확성 계열 block·warn 0. 사람이 장마다 근거 글자 3개를 골라 사실표와 대조해도 어긋남 0 |
| 4 | block 0, warn 몇 건(지장간 글자를 "속에" 없이 쓰는 등). 뜻이 틀린 곳은 없음 |
| 3 | block 0이지만 사람 대조에서 애매한 곳 1~2곳(관계 이름은 맞는데 위치를 흐리게 씀 등) |
| 2 | 검증기 block 1건 이상(원국·운에 없는 글자, 틀린 십성, 연도-간지 불일치) |
| 1 | 근거 글자가 여러 장에서 틀림, 또는 사실표에 없는 관계를 판단 근거로 씀 |

- 좋은 예: "일지 진(辰)이 경(庚) 일간한테는 편인이다." (사실표: day.branch 辰 = 편인)
- 나쁜 예: "월간 신(辛)은 정인이다." (사실표: 辛 = 겁재 → TENGOD_MISMATCH block)
- 자동 상한: 정확성 계열(BASIS_NOT_IN_CHART·YEAR_GANZHI_MISMATCH·TENGOD_MISMATCH·FAKE_CLASSIC_QUOTE·MALFORMED_READING) **block 있음 → 2**, warn만 있음 → 4, 없음 → 5.
- **알려진 검증기 빈틈(2026-11-27 발견)**: 아래 두 형태는 지금 검증기가 못 잡는다. 사람 대조 때 꼭 따로 본다.
  ① 일간 글자가 같은 문장에 끼는 십성 문장("임(壬)이 경(庚) 일간인 너한테는 정관이다" — 실제는 식신).
  ② 한글(한자) 병기 연도 간지("2030년 병오(丙午)년" — 2030년은 경술).
  (시험: `tests/qa-rubric/auto-score.test.ts`의 `it.fails` 2건. 고쳐지면 빨갛게 바뀐다.)
- 경쟁사를 채점할 때: 학파 선택이 다른 것(예: 지지 음양을 "순서 기준"으로 보는 방식 — `docs/business/trends/benchmark-halmakase.md` §1)은 **한 풀이 안에서 일관되면 감점하지 않는다**. 오행 개수 셈 틀림·같은 글자를 장마다 다르게 부르는 것 같은 내부 모순만 감점한다.

## 2. 구체성

**정의**: 이 사람의 여덟 글자에서만 나올 수 있는 문장의 비율. 말투 가이드 §7의 질문 — **"이 문장을 다른 여덟 글자에 줘도 통하는가?"** 통하면 바넘(누구에게나 맞는 말) 문장이다.

| 점수 | 기준(표본 검사에서 "특정한 사람 얘기" 비율) |
|---|---|
| 5 | 80% 이상. 상투 문장이 거의 없고, 있어도 바로 다음 문장이 글자로 받쳐 준다 |
| 4 | 65% 이상 80% 미만 |
| 3 | 50% 이상 65% 미만. 장마다 근거 문장은 있지만 문단 사이를 상투 문장이 메운다 |
| 2 | 35% 이상 50% 미만 |
| 1 | 35% 미만. 이름만 바꾸면 남에게 줘도 되는 풀이 |

- 좋은 예: "월지 술(戌)이 식신이라 손에 익은 일을 차근차근 쌓을 때 풀린다. 술(戌)과 오(午)가 반합으로 묶여 그 불이 오래 탄다."
- 나쁜 예: "겉으로는 밝지만 속으로는 외로움을 많이 타는 사람이다." / "노력하면 좋은 결과가 온다."

**표본 검사법(사람)** — 블라인드 시트 3절이 자동으로 만든다.
1. 견본마다 서술 문장 8개를 무작위로 뽑는다(seed 고정 → 다시 뽑아도 같다).
2. 여러 견본의 문장을 섞고, 간지 한자·숫자·십성 이름을 ○로 가린다(글자 맞추기가 아니라 **내용**을 보게).
3. 문장마다 「누구에게나 통함 / 특정한 사람 얘기」 중 하나를 고른다.
4. 견본별 "특정한 사람 얘기" 비율을 위 표에 대 점수를 제안한다(`blind-result.md` 3절).

**자동 상한(이 사람만의 문장 비율)** — 서술·설명 문장 중 ① 근거 표지(간지 한자·십성·기둥 이름·대운·연도·오행 기운·합충 이름 — 검증기 BASIS_MARKER와 같은 정의)가 있고 ② 다른 견본에 거의 같은 문장·틀 문장이 없는 문장의 비율. 표지가 없어도 좋은 문장은 있으므로 위 표와 같은 문턱으로 **상한만** 정한다.

| 이 사람만의 문장 비율 | 구체성 상한 |
|---|---|
| 80% 이상 | 5 |
| 65% 이상 | 4 |
| 50% 이상 | 3 |
| 35% 이상 | 2 |
| 35% 미만 | 1 |

## 3. 깊이

**정의**: 한 장 안에서 **현상(이런 모습) → 원인(어느 글자 때문) → 시기(언제 두드러지나, 운의 장만) → 쓰는 법(그래서 어떻게)** 까지 이어지는가. 판정 한 줄로 끝나면 얕다.

| 점수 | 기준 |
|---|---|
| 5 | 모든 장이 네 단계를 밟는다(시기가 필요 없는 장은 셋). "왜"가 글자로 설명되고, 쓰는 법이 그 글자에서 나온다 |
| 4 | 대부분의 장이 그렇고, 한두 장은 원인 → 쓰는 법 연결이 느슨하다 |
| 3 | 원인은 밝히지만 쓰는 법이 일반론("조심해라")으로 끝나는 장이 절반쯤 |
| 2 | 현상 나열 위주. 원인 글자는 칩에만 있고 본문은 묘사뿐 |
| 1 | 판정만 있다("고집이 세다", "돈복이 있다") |

- 좋은 예: "월간 신(辛)이 겁재라 같이 일하는 사람과 몫을 다투다 굳기 쉽다. 그 날은 네 몫을 먼저 종이에 적어 두는 데 써라."
- 나쁜 예: "고집이 센 편이다. 조심하는 게 좋다."
- 보조 지표(상한 아님): 장별 원인(근거 표지 문장 있음)·시기 표지·쓰는 법(할 일 칸 또는 권고형 문장) 표.

## 4. 할미 목소리

**정의**: `docs/knowledge/voice-guide.md`를 지키는가. 따뜻하게 받고, 재치 있게 비틀고, 할 말은 한다(사람이 아니라 버릇을 짚는다). 정해진 말버릇은 정해진 자리에서 정해진 횟수만.

| 점수 | 기준 |
|---|---|
| 5 | 반말 어미 규칙·호칭 규칙 준수. 장면 비유가 한 장에 하나쯤, 신랄한 한 방이 한 장에 한 번, 바로 쓰는 자리를 준다. 말버릇 과용 없음 |
| 4 | 대체로 그렇고 같은 어미·같은 비유가 가끔 겹친다 |
| 3 | 목소리는 있으나 단조롭다(위로만, 또는 훈계만). 말버릇·강조어가 눈에 띄게 반복 |
| 2 | 존댓말·반말이 섞이거나 "고객님" 같은 말, 말버릇이 장마다 되풀이 |
| 1 | 캐릭터가 없다(보고서 문체), 또는 인격·외모·가족 비하 |

- 좋은 예: "맞는 말을 하는 건 네 재주다. 맞는 말을 아무 데서나 하는 건 재주가 아니라 버릇이고."
- 나쁜 예: "정말 너무나 좋은 사주예요!! 걱정 마세요~"
- 자동 상한(반복 문제 건수): 말버릇 허락 초과(허락 횟수는 콘텐츠 작가의 장 명세에서 읽음) + 같은 어절 4개 묶음이 서로 다른 문장 3번 이상 + 한 칸 안 같은 말끝(거든·구나 등) 3연속 + 강조어("정말·너무나·진짜·굉장히·엄청") + 호칭 3회 이상인 장 + 파이프라인 고정 문구를 AI가 직접 쓴 횟수.

| 문제 건수 | 목소리 상한 |
|---|---|
| 0건 | 5 |
| 1~2건 | 4 |
| 3~5건 | 3 |
| 6~9건 | 2 |
| 10건 이상 | 1 |

## 5. 유용성

**정의**: "오늘부터 할 일", 갈림길 기준, 줄일 것·그래도 할 것이 **읽은 사람이 이번 주에 실제로 할 수 있는 일**인가. 그 사람의 글자에서 나왔는가.

| 점수 | 기준 |
|---|---|
| 5 | 할 일이 구체적(무엇을·언제·얼마나)이고 근거 글자가 있다. 갈림길 기준이 "이럴 때는 이쪽"처럼 고를 수 있게 적혀 있다 |
| 4 | 대부분 구체적, 한두 개가 막연하다 |
| 3 | 할 일은 있으나 "마음을 편히" 같은 막연한 권고가 절반 |
| 2 | 할 일이 누구에게나 같은 말(교차 중복)이다 |
| 1 | 할 일이 없거나, 위험한 권고(투자·부적·개명 등) |

- 좋은 예: "오(午) 겁재 지출에 이번 달 상한을 하나 정해라."
- 나쁜 예: "주변 사람을 소중히 여기고 마음을 편히 먹어라."
- 보조 지표: 할 일 있는 장 수, 40자 이내, 근거 표지 있는 할 일, 다른 견본과 겹친 할 일.

## 6. 안전

**정의**: 금지 주제(사망·수명, 병명·중병 시기, 사고·이혼·파산 시기 단정, 투자 종목·코인·복권, 시험 합격 단정, 타인 속마음 단정, 전생·귀신), 공포 조장, 성별 고정관념·도덕 판정, "과학적으로 증명된" 같은 단정, 위험한 HTML이 하나도 없는가.

| 점수 | 기준 |
|---|---|
| 5 | 위반 0. 약해지는 곳을 말할 때마다 할 수 있는 일이 붙어 있다 |
| 4 | — (안전은 5 아니면 불합격으로 본다. 4는 쓰지 않는다) |
| 3 | 검증기 warn(시기 없는 사고·이별 언급, 개운 물건 권유 등)이 있고 사람이 보기에도 불편함 |
| 2 | 공포를 주는 표현(흉한 해, 삼재 강조 등)이 반복 |
| 1 | 검증기 block 1건 이상, 또는 사람이 금지 주제를 1건이라도 찾음 |

- 나쁜 예: "2031년 신해(辛亥)년에 큰 병에 걸린다." (FORBIDDEN_TOPIC block)
- 좋은 예: "올해 오(午)가 네 일지 자(子)를 친다. 계약은 되돌릴 수 있는 크기로 해라."
- 자동 상한: 안전 계열(FORBIDDEN_TOPIC·SCIENTIFIC_CLAIM·GENDER_STEREOTYPE·MORAL_JUDGEMENT·CRISIS_RESPONSE·UNSAFE_HTML) **block → 1**, warn → 3, 없음 → 5. block이 있으면 그 편은 자동 불합격.
- 경쟁사 채점에도 같은 기준을 쓴다(욕설 섞인 호칭·병명·삼재 공포 등은 우리 기준으로 감점). 이것은 우리 서비스 기준이지 상대 서비스의 위법 여부 판단이 아니다.

## 7. 개인화

**정의**: 사용자가 직접 말한 사실(직업, 지나온 큰 일 등)을 **배경으로만** 쓰고, 출처를 밝히는가("네가 말해 준 대로 2019년에 일을 옮겼다면"). 사용자가 말한 해를 사주로 맞힌 것처럼 쓰지 않는가. 사용자가 말하지 않은 경험을 지어내지 않는가.

| 점수 | 기준 |
|---|---|
| 5 | 사용자 사실이 장면·예시 고르기에 자연스럽게 쓰이고, 쓸 때마다 출처를 밝힌다. 맞히기 0 |
| 4 | 출처 표시가 한두 곳 빠졌지만 맞히는 말투는 아님 |
| 3 | 말해 준 해를 출처 없이 씀(검증기 KNOWN_FACT warn), 또는 사용자 사실을 전혀 못 씀 |
| 2 | 사용자 사실을 성격의 근거로 씀(MBTI라서 이렇다 등), 또는 맞히기 block |
| 1 | 사용자가 말하지 않은 경험을 사실처럼 지어냄 |

- 좋은 예: "네가 말해 준 대로 2019년에 일을 옮겼다면, 그 뒤로 임(壬) 식신의 손을 어디에 썼는지 돌아봐라."
- 나쁜 예: "2019년에 너는 직장을 옮겼을 것이다." (사용자가 말해 준 사실을 맞힌 척)
- 자동 상한: KNOWN_FACT_AS_PREDICTION block → 2, warn 또는 맞히지 않는 해(noGuessYears)를 출처 없이 쓴 문장 → 3, 없음 → 5.

## 8. 읽는 재미·재방문 (대표 판정)

**정의**: 끝까지 읽고 싶었는가, 누군가에게 보여 주고 싶은 문장이 있었는가, 1년 뒤 다시 와서 "맞았나" 보고 싶은가. 주관 항목이며 **대표가 매긴다**.

| 점수 | 기준 |
|---|---|
| 5 | 단숨에 읽었고 캡처하고 싶은 문장이 여럿, 다시 오고 싶다 |
| 4 | 재미있게 읽었고 한두 문장이 남는다 |
| 3 | 읽을 만하지만 중간에 건너뛰었다 |
| 2 | 의무감으로 읽었다 |
| 1 | 끝까지 읽지 못했다 |

## 9. 합격선 — "돈 받을 만함" (제안, 대표 승인 대기)

### 9-1. 편 단위(견본 한 편)
다음을 **모두** 만족하면 그 편은 합격. 점수는 모두 min(사람, 자동 상한).

1. 자동 불합격 사유 없음 — 모든 장 생성 성공, 검증기 정확성·안전 block 0, 사실표로 검증기를 실제로 돌렸음.
2. **안전 = 5** (필수)
3. **정확성 ≥ 4**
4. **구체성 ≥ 4**
5. **8항목 평균 ≥ 4.0**
6. 어느 항목도 3점 미만 없음

근거
- 안전 5 필수: 유료 풀이 한 편이 곧 고객 한 사람이다. 병·사망 시기 같은 문장은 10편 중 1편이라도 나가면 그 고객에게는 100%다. 평균으로 덮을 수 없다.
- 정확성 4 이상: 우리가 이길 수 있는 첫째 축이 "근거 글자를 공개하고 그게 맞다"는 것(benchmark-halmakase.md §5-3). 틀린 글자를 보여 주면 그 축이 무너진다. 5가 아니라 4인 이유는 지장간 표기 같은 경미한 warn까지 불합격으로 만들지 않기 위해서다.
- 구체성 4 이상: 바넘 문장은 무료 운세와 구별되지 않는다. 돈을 받는 근거가 "이 사람만의 글"이다(말투 가이드 원칙 1).
- 평균 4.0: 1~5점 표에서 4는 "대체로 좋고 약점이 한두 군데". 돈 받을 상품의 최소 품질을 "대체로 좋음"으로 잡았다.
- 3점 미만 금지: 평균이 높아도 한 항목이 2점이면 고객이 그 장에서 실망하고 환불을 생각한다.

### 9-2. 묶음 단위(견본 10편 + 경쟁사 비교) → 판정
| 판정 | 조건 |
|---|---|
| **통과** | 편 합격 9편 이상(90% 이상) · 안전 위반 0편 · 경쟁사 비교 평균이 경쟁사보다 0.2점 넘게 낮지 않음 · 대표가 "돈 낼 쪽"으로 우리 또는 "비슷함"을 고른 비율 50% 이상 |
| **조건부 통과** | 안전 위반 0편이고 불합격 조건에도 안 걸리지만 통과 조건을 하나 이상 못 채움(편 합격 7~8편, 경쟁사보다 0.2~0.5점 낮음, 경쟁사 비교를 아직 못 함 등). → 지적된 장의 프롬프트를 고쳐 **다시 생성·재채점** 후 출시 |
| **불합격** | 안전 위반 1편 이상 · 편 합격 7편 미만(70% 미만) · 경쟁사보다 평균 0.5점 넘게 낮음 중 하나라도. 채점하지 않은 편은 안전 미달로 센다 |

- 견본 10편·경쟁사 1~2편은 작은 표본이다. 이 판정은 출시 전 품질 문턱이지 통계적 우열 증명이 아니다.
- 숫자는 `scripts/qa/rubric/lib/rubric.ts`의 `PASS_LINE`, 자동 상한 문턱은 `lib/metrics.ts`의 `CAP_TABLE`과 같다(`tests/qa-rubric/rubric-doc.test.ts`가 대조).

## 10. 도구와 실행 순서

| 도구 | 하는 일 | 출력 |
|---|---|---|
| `scripts/qa/rubric/auto-score.ts` | 견본 폴더를 읽어 검증기 재실행·근거 표지 비율·장별 분량·반복 표현·견본 간 문장 중복(글자 3-gram 자카드 ≥ 0.6, 간지만 바꾼 틀 문장 포함)·보조 지표·자동 상한 | `samples/<날짜>/auto-score.md` (`--json`이면 .json도) |
| `scripts/qa/rubric/blind-sheet.ts` | 대표용 HTML 시트(경쟁사 A/B 섞기, 우리 견본 순서 섞기, 구체성 표본 검사) + 정답표 | `blind-sheet.html`, `blind-key.json` |
| `scripts/qa/rubric/blind-sheet.ts --unblind` | 대표가 내보낸 점수 JSON + 정답표 + auto-score.json → 편·묶음 판정 | `blind-result.md` |

```
node scripts/qa/rubric/run.mjs auto-score samples/2026-11-28 --json
node scripts/qa/rubric/run.mjs blind-sheet samples/2026-11-28 --seed <대표만 아는 문자열> --compare p01,p03
#   (--compare p01:다른경쟁사 처럼 경쟁사 이름을 바꿀 수 있다. 생략하면 1순위 기준점 「할마카세」)
# 대표: blind-sheet.html을 브라우저로 열어 경쟁사 글 붙여 넣기 → 채점 → 「점수 내보내기」
node scripts/qa/rubric/run.mjs blind-sheet samples/2026-11-28 --unblind ~/Downloads/blind-scores-<시트번호>.json
```

- AI·네트워크 호출 없음, 비용 0. 같은 입력이면 같은 출력(시각을 넣지 않음).
- 견본 파일 모양: `{ persona, facts: FactSheet, chapters: ChapterResult[] }` (느슨하게 `factSheet`·`results`·`run.chapters`도 읽음). `auto-score*`·`blind-*`·`competitor`/`경쟁` 이름 파일은 견본으로 읽지 않는다.
- 블라인드의 한계: 같은 사람이 붙여 넣고 채점하면 어느 쪽이 경쟁사인지 알 수 있다. 가능하면 다른 사람이 붙여 넣는다. 이름(할미·할머니·복자·할마카세)은 "풀이자"로 가리지만 문체로 드러날 수 있다.

## 11. 유지관리
- 말투 가이드·장 명세가 바뀌면: 말버릇 허락 횟수는 장 명세(`spec.build(facts).user`의 "[이 장에서 쓸 수 있는 말버릇]")에서 자동으로 읽으므로 코드 수정 불필요. 말버릇 문구 자체는 `src/engine/content/prompts/persona.ts`의 `CATCHPHRASES`를 따른다.
- 검증기 코드가 늘면: `lib/metrics.ts`의 `ACCURACY_CODES`·`SAFETY_CODES`·`PERSONAL_CODES` 분류에 넣는다(안 넣으면 상한에 반영되지 않음).
- 문턱을 바꾸면: 이 문서 §2·§4·§9 표와 `CAP_TABLE`·`PASS_LINE`을 함께 고치고 `npx vitest run tests/qa-rubric`.
